# BTR quality release: verification scope

This release preserves Watch and the existing welcome screen. It strengthens the evidence studio, Truth Lab, audience explanations and judge demonstration.

## User journey

1. Open Truth Lab and choose the evidence-change demonstration.
2. Change the defender tracking. Inspect withdrawn, preserved and uncertain claims.
3. Expand beginner vs analyst explanations: the former teaches the football concept; the latter combines positional limits with completed-pass forward progress.
4. Challenge the crew using the same snapshot. Choose an opening, challenge or measurement review.
5. Use the 90-second demonstration in reviewed mode (no requests) or live mode (at most two requests, with clear cached/fresh/fallback labels).

## Validation

- Full Node test suite: 188 passed, zero failed.
- Desktop browser: correction chapters, analyst mode, evidence-to-crew handoff inspected.
- 390 × 844 browser viewport: correction ledger, audience comparison and demonstration inspected; no page-width overflow observed.
- Stream interruption and HTTP 429 are tested; partial output cannot become a completed review.
- Open audience details survive replay updates. The audit is outside collapsed evidence drawers.
- Real iPhone/Android hardware, VoiceOver/TalkBack, independent viewers and a recorded submission video have NOT been verified in this session.

## Model and evaluation honesty

The evidence studio uses one Azure planner and deterministic evidence tools. Five named roles are source-rendered contributions, not five independent models. The film discussion has its own existing architecture. No automatic calibrated video tracking is claimed.

The v62 comparison retained all 12 paired cases: production passed 11/12 validation checks with 12/12 rubric-matched tools; baseline passed 7/12 with 5/12 rubric matches. A corrected stationary defender was incorrectly labeled missing tracking by one model proposal. The guard rejected it. The initial live demonstration also encountered this issue and displayed the reviewed fallback.

Version v62.1 explicitly distinguishes known zero movement from absent tracking. Its follow-up comparison uses new numeric packets with a new fixed seed but the same fixture structure. It is not an independent blind evaluation. Both raw reports are retained; no failures are deleted.

These comparisons measure tool selection, references, latency and tokens. They do not establish general factual accuracy, multi-agent superiority, or viewer satisfaction. Token totals are usage measurements, not an Azure invoice.

That proposal was rejected; its full two-round record is retained in quality-live-v62-1.json. Version v62.2 limits both benchmark arms to currently available tools and evidence IDs through the structured-output schema, while independent validation still checks the chosen tool’s cited inputs.

## Final measured result

v62.2 production and minimal baseline both passed 12/12 tool/citation checks. Production matched the developer relevance rubric in 12/12 cases versus 5/12 baseline. Median latency: 956 ms versus 1,027 ms. Total tokens: 9,595 versus 6,864, about 40% more for production. Both arms used 12 model requests. This is a small developer evaluation, not an independent superiority result.

Final browser live demonstration: two fresh verified Azure rounds (1,155 ms and 1,425 ms). Full receipts retained in quality-live-v62-2.json. Pause, chapter jump and resume were exercised to reach the correction; this was not a recorded 90-second submission video. Earlier runs exercised the full timer to 90 seconds.
