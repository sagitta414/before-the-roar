# v145 automatic event detection proof

## What changed

BTR now derives player locations, ball locations, possession changes, completed passes, interceptions and shot candidates from decoded pixels in the one-minute synthetic training video. The detector uses the fixed-camera pitch calibration and enrolled fictional kit-marker colours. It does not receive the event schedule or the source coordinates used to render the video.

The v145 detector adds illumination-tolerant chromatic matching, geometry-aware component selection, per-marker evidence support, frame-level detector health and a 0.3-second ball-occlusion grace period. A longer loss of the ball or player evidence withholds event inference. Each inferred event exposes its frame range, identities, distance, ground-plane speed and heuristic evidence-support tier. The support score is not presented as a calibrated probability.

## What the result establishes

The study establishes that the deterministic detector can recover the intended event chain from unfamiliar videos generated by the same controlled synthetic family, including difficult lighting and compression treatments. It also proves that the public UI can disclose degraded evidence, pause on brief occlusion and withhold unsupported conclusions.

It does not establish accuracy on independent real-world or Premier League footage. The current supported envelope is a fixed, calibrated camera; a known ground-plane scale; visible enrolled colour markers; and a high-visibility ball. The system does not yet support moving cameras, facial player identification, unmarked broadcast players, reliable aerial-ball speed, or automatic goal certification. Shot results remain candidates for editorial review.

## Reproducibility and cost

- Development evaluator: `node scripts/evaluate-tracking.mjs`
- Historical frozen-condition result: `docs/proof/tracking-holdout.json`
- Current-release study and portable runner: `node scripts/tracking-holdout.mjs --publish` (requires Python 3 and ffmpeg; `BTR_PYTHON` and `BTR_FFMPEG` may specify their paths)
- Machine-readable development result: `dist/assets/tracking/validation.json`
- Machine-readable frozen result: `dist/assets/tracking/holdout.json`
- Detector tests: `node --test tests/tracking-model.test.mjs tests/auto-eventing-v145.test.mjs`

Pixel detection, tracking and event inference run deterministically in the browser and use no model request. Azure AI is optional and begins only when the detected evidence is sent to the editorial agents for explanation.
