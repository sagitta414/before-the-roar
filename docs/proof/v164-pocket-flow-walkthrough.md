# v164 — Pocket Director step-by-step flow

## 1. Live

The match strip answers who, score and time. The cinematic moment remains the first large surface. “Why this matters” opens the evidence explanation without changing the current moment.

## 2. Live Director

The default state shows only the current verified cue. “More” reveals the next visual clue, proof status and device tools. This keeps operational controls out of the initial reading path.

## 3. Feel the Match

The default state is one compact accessibility row with a direct on/off action. Cue training is hidden behind “Learn the four cues.” The expanded panel lets a user preview pressure, possession, shot and correction patterns. Preview controls remain explicitly separate from live event cues.

## 4. Match data and evidence

The match dashboard stays collapsed until “Open” is selected. The evidence map remains available farther down the Live screen for users who want player positions and source records. This separates watching from investigation.

## 5. Views and Perspective Director

The first action on Views is now creating a recap. Player, tactical, beginner, disputed-claim and Spanish studio presets are visible as one swipeable prompt rail. The result includes timestamps, narration, overlays, evidence IDs and correction status. Explanation modes follow as compact cards rather than a tall two-column wall.

## 6. Player

Player Focus leads with the selected player, reached event count and displacement. The portrait is shorter, and the horizontal squad selector changes the focus without changing the evidence cutoff.

## 7. Lab

Truth Lab presents the recorded and simulated evidence side by side. The AI crew follows as a separate action for questions. The shorter introduction brings both tools closer to the first mobile viewport.

## 8. Navigation

Four persistent destinations map to four user jobs: Live, Views, Player and Lab. Every screen change resets to its top and preserves the shared cue, time, source and correction state.

## Verification boundary

The automated review verifies structure, default disclosure state, primary-action order, cache delivery and deterministic cue and recap logic. Browser sound, speech and vibration support still varies by device and requires physical-device accessibility testing before claiming certified accessibility.
